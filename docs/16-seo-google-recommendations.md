# 16 – SEO and Google-Friendly Recommendations

Goal: make the site easy for Google to crawl, understand and rank, and pass Core Web Vitals.

## 1. Rendering strategy (most important for a frontend-only React app)
Google can run JavaScript, but a pure client-rendered SPA is slower to index and weaker for sharing previews. Recommended order:
1. **Pre-render static HTML at build time** (e.g. `vite-plugin-ssg`, `vite-react-ssg`, or `react-snap`) for: home, every category, every product, static pages. Because data is local JSON this is easy and needs no server.
2. If that is not possible, keep the SPA but make sure each route sets its own `<title>`, meta description, canonical and structured data via `react-helmet-async`.
3. Alternative: build with Astro or Next.js static export using the same specs.

## 2. Per-page metadata
| Page | Title pattern (≤ 60 chars) | Description (≤ 155 chars) |
|---|---|---|
| Home | `Haven & Oak – Modern Furniture for Every Room` | Unique summary + value props |
| Category | `{Category} – Shop {n}+ Styles \| Haven & Oak` | Category benefit + CTA |
| Product | `{Product title} \| Haven & Oak` | First feature sentence + price |
| Search | `Search results for "{q}"` + `noindex` | – |
| Cart / Checkout / Order | `noindex, nofollow` | – |

Every page: `<link rel="canonical">`, `og:title`, `og:description`, `og:image`, `og:type`, `twitter:card=summary_large_image`, `<meta name="viewport">`, `<html lang="en">`, theme-color `#1F4D3F`.

Canonical rules: strip `sort`, `page=1`, tracking params. Filtered URLs with multiple facets → canonical to the base category (or `noindex,follow`).

## 3. Structured data (JSON-LD)
Add via Helmet as `<script type="application/ld+json">`.

**Organization + WebSite (home)**
```json
{
  "@context": "https://schema.org",
  "@graph": [
    { "@type": "Organization", "name": "Haven & Oak", "url": "https://example.com", "logo": "https://example.com/logo.png" },
    { "@type": "WebSite", "url": "https://example.com",
      "potentialAction": { "@type": "SearchAction",
        "target": "https://example.com/search?q={search_term_string}",
        "query-input": "required name=search_term_string" } }
  ]
}
```

**Product (PDP)**
```json
{
  "@context": "https://schema.org",
  "@type": "Product",
  "name": "Harlow 3-Seat Power Reclining Sofa",
  "image": ["https://example.com/images/products/HO1042-1.webp"],
  "description": "…",
  "sku": "HO1042",
  "brand": { "@type": "Brand", "name": "Haven & Oak" },
  "offers": {
    "@type": "Offer",
    "url": "https://example.com/p/harlow-power-sofa-HO1042",
    "priceCurrency": "USD",
    "price": "1299.99",
    "availability": "https://schema.org/InStock",
    "itemCondition": "https://schema.org/NewCondition"
  }
}
```
- Only add `aggregateRating` / `review` if the reviews are **real**. Fake or placeholder review markup violates Google's guidelines and can trigger a manual action. For the demo, leave them out.

**BreadcrumbList** on category and product pages. **FAQPage** only on pages that visibly show the FAQ.

## 4. Crawl files
`public/robots.txt`
```
User-agent: *
Allow: /
Disallow: /cart
Disallow: /checkout
Disallow: /order/
Disallow: /search
Sitemap: https://example.com/sitemap.xml
```
`sitemap.xml`: generated by a build script (`scripts/generate-sitemap.mjs`) listing home, categories, products, static pages with `lastmod`.

## 5. Content and URLs
- Clean, lowercase, hyphenated URLs; no hash routing for the production site (hash URLs are not indexed separately).
- One `<h1>` per page, keyword-relevant but natural.
- Original descriptions (50–150 words) for each product; avoid duplicate text across products and never copy from other retailers.
- Internal linking: breadcrumbs, related products, category hubs, footer links.
- Image `alt` text and descriptive file names.
- Real 404 page; if hosting allows, return HTTP 404 status for unknown URLs.

## 6. Core Web Vitals targets
| Metric | Good threshold |
|---|---|
| LCP | ≤ 2.5 s |
| INP | ≤ 200 ms |
| CLS | ≤ 0.1 |

See `docs/17-performance.md` for how to reach them.

## 7. Google Merchant Center (optional, for real stores)
Generate a product feed file (`scripts/generate-merchant-feed.mjs` → `public/feed.xml` or TSV) from `products.json` with: id, title, description, link, image_link, price, availability, brand, condition, google_product_category. Submit in Merchant Center for free listings.

## 8. Demo vs. production
If the catalogue is fake/demo content, add `<meta name="robots" content="noindex">` site-wide until real products and policies are in place. Do not publish fake prices or reviews as if they were real offers.

## 9. Analytics (optional)
If Google Analytics is added, load it after consent, async, and document it in the privacy page. Not required for the core build.

## 10. Verification checklist
- [ ] Search Console property verified, sitemap submitted
- [ ] URL Inspection shows rendered HTML contains products
- [ ] Rich Results Test passes for Product and Breadcrumb
- [ ] Lighthouse SEO ≥ 95, Mobile-Friendly
- [ ] No pages blocked unintentionally
